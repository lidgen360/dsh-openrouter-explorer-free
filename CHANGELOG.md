## 0.8.3 — 2026-11-09

- **В селектор чата больше не попадают модели не для чата.** Критерий `isChatCapable`: текст на входе,
  **только текст** на выходе и без `audio`/`video` во входных модальностях. Под него подтянуты:
  «Едем на халяву» (`isFreeChatModel`), `use-model` (понятная ошибка вместо добавления в провайдера) и
  очистка провайдера (`pruneProviderChatModels`) — при старте и после каждого синка из маршрута `openrouter`
  удаляются модели, которые каталожно не подходят для чата; неизвестные каталогу ручные записи не трогаются.
- **В каталоге** такие модели получили бейдж **«не для чата»** с подсказкой (генерация — во вкладке «Генерация»).
- Причина: Lyria (выход `text+audio`), Crouton/Super VL/Nano Omni (вход `video`/`audio`) раньше проходили
  проверку «есть text», поэтому автороут и ручной выбор добавляли их в провайдера, и они висели в селекторе.
- Тесты: **70** (критерий chat-capable, отказ `use-model`, прунинг маршрута, no-op без редактора).

## 0.8.0 — 2026-11-09

- **Генерация доступна агенту как tools** (`src/host/tools.js`, регистрация через
  `ctx.tools.register`, опциональная инъекция `tools`):
  `openrouter_generate_image`, `openrouter_generate_video`, `openrouter_video_status`,
  `openrouter_generate_speech`. Агент может рисовать, запускать видео и озвучивать текст по просьбе
  пользователя; видео — submit + поллинг статуса со скачиванием MP4, поэтому long-running job не блокирует шаг.
- Tools возвращают **путь к сохранённому файлу и его URL** (плюс стоимость, если API её отдал), а модель
  можно не указывать — берётся первая из discovery. Ошибки API приходят как обычные tool-ошибки с текстом.
- Отключается `tools: false` в конфиге строки; без сервиса `tools` (headless/SDK без агента) регистрация —
  тихий no-op, плагин остаётся универсальным.
- **Тесты: 65** (tools: регистрация/диспоуз, JSON Schema, авто-модель, ошибки, видео-поллинг и скачивание;
  entry-тест обновлён под вторую опциональную инъекцию).

- **Тесты: 56** (адаптеры генерации + сохранение файлов, кэш моделей, отсутствие ключа, безопасность имён).
  Живой discovery проверен на реальных API: 63 image / 33 video / 38 speech моделей.

## 0.5.0 — 2026-11-08

Аудит журнала и состояния нашёл три реальных бага — исправлены:

- **Журнал жил вечно**: события хранились без срока, только по счётчику 500. Теперь есть окно хранения
  `journalDays` (по умолчанию **90 дней**), старые события и замеры синка вычищаются при каждом обновлении.
  В статусе появился блок `journal: { events, unread, oldest_at, retention_days }`.
- **Несколько профилей затирали состояние друг друга**: сервис держал снапшот в памяти и перезаписывал файл
  целиком — второй процесс (Web GUI + headless CLI на одном `DSH_HOME`) терял чужие изменения. Теперь каждый
  запрос перечитывает файл, а запись идёт под межпроцессным локом (`state.json.lock`, с очисткой протухшего
  лока). История цен и журнал общие и не теряются.
- **Повторное объявление «скоро исчезнет»**: признак уведомления хранился только в самих событиях, поэтому
  после вытеснения события из лимита модель объявлялась снова. Метка `expiry_event_at` теперь живёт в записи
  модели и переживает вытеснение; старые состояния мигрируются один раз без дублей.

Состояние переезжает со старого пути `~/.dsh/openrouter-models/state.json` на новый
`~/.dsh/openrouter-explorer-free/state.json` при первой записи (старый файл остаётся как бэкап).

Ещё по аудиту: лимиты подтверждены симуляцией 120 дней — события ≤ 500 и в пределах 90 дней, история цен
≤ 60 точек на модель, `syncs` ≤ 30, удалённые модели вычищаются через 90 дней, файл состояния остаётся
~300 КБ. Тесты: 33 (добавлены retention, дубли, гонки двух инстансов, сериализация локом).
