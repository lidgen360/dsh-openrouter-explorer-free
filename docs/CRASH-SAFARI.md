# Safari: падение WebContent (JavaScriptCore JIT)

Статус: **известная проблема окружения Safari**, не исключение плагина.

## Симптом

Чат/вся страница DSH Web GUI внезапно пропадает, вкладка перезагружается или показывает
белый экран. В `~/Library/Logs/DiagnosticReports` появляется
`com.apple.WebKit.WebContent-*.ips`:

```
exception: EXC_BREAKPOINT (SIGKILL)
faultingThread 0:
  WTFCrashWithInfoImpl(...)
  JSC::CodeBlock::setOptimizationThresholdBasedOnCompilationResult(...)
  JSC::JITToDFGDeferredCompilationCallback::compilationDidComplete(...)
```

Это ассерт **JavaScriptCore** (движка Safari) во время JIT-компиляции. Процесс
`com.apple.WebKit.WebContent` убивается целиком, поэтому «падает окно чата» — на самом деле
умирает renderer всей страницы, включая панель плагина.

## Что делает плагин, чтобы снизить риск

- Каталог рендерит 120 строк с кнопкой «Показать ещё», а не все 400+;
- опрос вкладки раз в 2 минуты, обновление состояния только при реальном изменении снапшота;
- галерея ограничена 8 карточками, видео не создаёт `<video>`-элементы, картинки lazy;
- тяжёлые вычисления (сравнение, рейтинги) выполняются только по действию пользователя.

## Обходные пути

1. **Открыть DSH Web GUI в Chrome/Chromium** — там другой JS-движок (V8); этот класс крашей
   не воспроизводится. Адрес тот же: `http://127.0.0.1:3080`.
2. **Обновить Safari/macOS** — ассерт относится к JIT; в новых сборках WebKit он может быть исправлен.
3. **Safari Technology Preview** — если нужен именно Safari.
4. Если краш повторяется на пустой вкладке без открытой панели плагина — это точно не плагин:
   пришлите самый свежий `.ips` из `~/Library/Logs/DiagnosticReports`.

## Как проверить, что дело в renderer'е

- Краш-репорт есть, но в DSH-логах и в консоли браузера нет JS-исключения плагина.
- После перезагрузки вкладки состояние чата восстанавливается из сессии — это признак того,
  что упал renderer, а не модель/хост.
